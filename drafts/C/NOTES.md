# 시안 C — 정책 판정기

## 콘셉트

이 사람의 강점은 "AI 에이전트를 만들었다"보다 "에이전트가 무엇을 해도 되는지를 코드로 정하고 그 판단을 운영해 봤다"에 있다고 봤습니다. 그래서 첫 화면 오른쪽(모바일은 제목 바로 아래)에 방문자가 직접 만져 보는 정책 판정기를 두었습니다. 스레드가 요청 → 초안 → 👍 → 답글 → 재시도로 진행되는 동안, 에이전트가 부르려는 도구 호출 일곱 줄이 정책 함수 선을 지나 허용·사람 답 필요·거부 칸으로 갈라집니다. 단계를 누르면 판정이 바뀌고, 줄을 누르면 코드가 확인하는 순서와 모델에게 돌려주는 이유를 보여 줍니다. 판정은 agent-colleague 의 실제 정책 코드와 같은 조건·같은 순서로 계산합니다. 미감은 모눈종이, 등폭 숫자, 신호등 세 색(허용 초록·사람 호박·거부 빨강)으로 정밀하게 잡되, 따뜻한 종이색 바탕과 사람 색(호박)을 앞에 두어 차갑지 않게 했습니다. 그 아래로 15주 운영 기록, 설계 요점, 다른 작업물, 글, 연결이 이어집니다.

## 왜 시선을 끄는지

- 30초 안에 "이 사람은 에이전트의 실행 권한을 코드로 설계했다"를 문장 대신 움직이는 표로 보여 줍니다. 자동 재생만 봐도 같은 도구가 단계마다 다르게 판정되는 것이 보입니다.
- 03 단계(👍만 단 상태)에서 티켓은 "👍 는 세지 않음", 무거운 운영 조회는 "👍 로 충분"으로 갈립니다. 실제 코드에 있는 비대칭이라 밋업의 개발자 청중이 물어볼 거리가 됩니다.
- 05 단계에서 같은 티켓 호출이 실행 기록 때문에 거부되는 것을 보여 줘, 중복 실행 방지를 설명 없이 전달합니다.
- 운영 상태를 현재형으로 말하지 않고, "재현 예시" 표시와 "판정은 정책 코드와 같은 조건을 같은 순서로 확인해 계산했습니다" 주석을 판정기 안에 넣었습니다.

## 인터랙션

| 대상 | 동작 |
|---|---|
| 자동 재생 | 다섯 단계를 2.8초(마지막 단계 4.2초) 간격으로 돌립니다. 판정기가 화면에 4분의 1 넘게 보일 때만 돌고, 그보다 덜 보이거나 탭이 숨겨지면 멈춥니다. 오른쪽 위 버튼으로 멈춤·다시 재생. |
| 단계 버튼 01~05 | 누르면 자동 재생이 멈추고 그 단계의 판정으로 바뀝니다. 판정이 바뀐 줄만 한 번 깜빡이고, 표시점이 새 칸으로 미끄러집니다. |
| 도구 호출 줄 7개 | 누르면 아래 "판정 순서" 칸이 그 줄의 확인 순서(예·아니오·확인 안 함), 결과, 모델에게 돌려주는 이유 요약 또는 실행 내용을 보여 줍니다. |
| 판정 순서 칸 높이 | 선택한 줄의 다섯 단계 중 가장 긴 높이로 고정해, 단계가 바뀌어도 아래 내용이 밀리지 않습니다. |
| `prefers-reduced-motion` | 자동 재생과 모든 애니메이션을 끄고 재생 버튼을 숨깁니다. 판정 순서 칸에 `aria-live="polite"`. |
| 자바스크립트 없음 | 01 요청 단계의 판정이 HTML 에 그대로 들어 있어 정적인 표로 읽힙니다. 재생 버튼과 "눌러 보세요" 안내는 숨깁니다. |
| 머리띠 | 지금 보는 절에 굵은 표시. 링크 탭 영역은 44px 이상. |

## 판정기 규칙과 출처

판정 로직은 `index.html` 끝의 `judge()` 하나입니다. 각 줄이 대응하는 실제 도구와 근거:

| 줄 | 실제 도구 | 근거 (agent-colleague) | 판정 |
|---|---|---|---|
| 티켓 만들기 | `jira_create` | `src/policy/index.ts` `orderPolicy`, `src/core/tools.ts` 의 `ordered_write` | ① 봇 글이 있나 ② 그 뒤 사람 글이 있나 ③ 같은 호출의 실행 기록이 없나. 셋 다 통과해야 허용. 👍 는 세지 않음 |
| 코드 고쳐 PR 올리기 | `code_start` | 같은 순서 정책. PR 은 결과에 바뀐 것이 있을 때 호스트가 올림(`src/session/tools.ts`, `docs/POLICY.md` 정책 표) | 위와 같음 |
| 운영 DB 쓰기 | `db_query` PROD `write:true` | `prodPolicy` 첫 줄 | 항상 거부 |
| 코드 검색 | 내장 `Grep`·`Glob` | `src/session/session.ts` `builtinVerdict` → `pathVerdict` | 경로가 저장소 폴더 안이면 허용 |
| 스레드에 글 올리기 | `slack_post` | `TOOL_CLASS` 가 `read` 라 조건 없이 허용, 핸들러가 이 스레드에만 올림. 도구 설명 "사람에게 말을 거는 유일한 길" | 허용 |
| 운영 DB 조회 · 가벼움 | `db_query` PROD 읽기 | `prodPolicy`, `docs/POLICY.md` "PROD 비용 정책" | 예상 비용이 상한 이하면 바로 허용 |
| 운영 DB 조회 · 무거움 | 같음 | 같음. 실행 기록은 보지 않음(POLICY.md: 조회는 다시 요청하면 같은 SQL 로 다시 돌아야 함) | ① 봇 글 ② 그 뒤 사람 글 또는 👍 |

- 검증: 정책 파일 세 개(`src/policy/index.ts`, `src/core/tools.ts`, `src/core/types.ts`)를 `/tmp/c_pol` 에 복사해 import 확장자만 고친 뒤, 실제 `decide()`·`pathVerdict()` 와 페이지의 `judge()` 를 5단계 × 7줄 = 35경우 대조했습니다. 허용·거부 불일치 0건. 거부일 때 페이지의 이유 요약이 실제 거부 문구와 같은 갈래인 것도 나란히 찍어 확인했습니다. (`/tmp` 사본은 남겨 두지 않아도 되는 임시 파일입니다.)
- "사람 답 필요"는 코드에서는 `deny` 입니다. 이유 문구로 다음 행동(초안 올리기, 사람 답 기다리기)을 알려 주는 거부를, 사람이 답해도 바뀌지 않는 거부(운영 쓰기, 이미 실행함)와 색으로 나눈 화면용 구분입니다.
- 코드에는 관리자 👍/👎 를 기다리는 `defer` 경로가 있지만 지금 이것을 내는 도구가 없어(POLICY.md) 판정기에 넣지 않았습니다.
- 이유 문구는 실제 거부 문구의 요약입니다. 비용 수치와 내부 용어 괄호를 뺐고, `PROD`·`DEV`·`ALPHA` 는 2편 원고 표현대로 운영·개발·검증 DB 로 바꿨습니다.

## 쓴 사실과 출처

- 15주·235건·96초(첫 답까지 중앙값)·46%(사람이 이어서 말한 스레드), "1편 봇부터 이어진 15주 운영 기록", 기간·9월 중순 전환·정확도 미측정 문장: 현재 사이트 `../../index.html` #featured 그대로.
- 설계 요점 세 개, 작업물(ai-ready, 매일메일), 글 소개문, 연결 문장, 푸터: 현재 사이트 그대로.
- 첫 화면 문장: 원본의 "만들고 운영합니다", "지금도 사내에서 답하고 있습니다"는 브리프가 금지한 현재형 단정이라 "만들고 운영했습니다"로 바꿨습니다. 부제는 #featured 의 15주·235건과 설계 요점 ①을 옮겨 쓴 것입니다.
- 글 목록의 2편 행: 원본에는 #featured 버튼으로만 있던 2편 링크를 글 목록에도 넣었습니다. 제목 "사내 AI 에이전트를 재설계한 이야기 2편"은 2편 원고(`agent-colleague-포트폴리오/2_블로그/blog-2-agent-colleague.md` 15행)와 링크 주소로 확인했습니다. 날짜·분량은 확인하지 못해 적지 않았습니다.
- 판정기 대화("이거 티켓으로 만들어 줘", "좋아요, 진행해 주세요"): policy-flow 그림 수준의 일반 예시. 사내 채널명·사람 이름·저장소명 없음.
- 그림 `assets/policy-flow.png`: `../../assets/featured/policy-flow.png` 와 같은 파일(cmp 로 확인).
- 연락처: GitHub, Medium (원본에 이메일은 없음). OG 이미지 주소는 원본과 같은 `/og-image.png`.

## 알려진 한계

- 데스크톱 1440x900 첫 화면에서 판정기의 "판정 순서" 칸 아래쪽은 접힘 아래로 내려갑니다. 단계·일곱 줄·판정까지는 첫 화면에 들어옵니다.
- 판정 순서 칸 높이를 고정했기 때문에, 짧은 상태(예: 무거운 조회의 03 단계)에서는 칸 아래에 빈 공간이 남습니다.
- 일곱 줄은 실제 도구 가운데 대표만 고른 것입니다. 개발·검증 DB, 이슈 삭제(프로젝트 제한), 센트리 조회, Bash 명령 검사 등은 판정기에 없습니다.
- 359px 이하에서는 단계 번호(01~05)를 숨깁니다. 320px 에서는 줄 이름이 두 줄로 접힙니다.
- 데스크톱의 policy-flow 그림은 400px 칸이라 글자가 작고, 눌러서 원본을 봐야 읽힙니다.
- 기존 `/og-image.png`(시안 폴더 밖)는 어두운 바탕에 "만들고 운영합니다"(현재형)가 적혀 있습니다. 이 시안을 쓰려면 OG 이미지를 새로 만들어야 하는데, 폴더 밖이라 만들지 않았습니다.
- 확인한 환경은 macOS headless Chrome 뿐입니다. 실기기(iOS Safari, Android Chrome)와 화면 읽기 프로그램으로는 확인하지 못했습니다.
- 390 폭 스크린샷은 iframe 래퍼 대신 Chrome DevTools Protocol 의 기기 에뮬레이션(`Emulation.setDeviceMetricsOverride`)으로 찍었습니다. 문서 폭이 390 인 것(`clientWidth`·`scrollWidth` 390)을 확인했습니다.
- Pretendard 는 jsdelivr 의 동적 서브셋 CSS 로 불러옵니다. 불러오지 못하면 시스템 글꼴로 보입니다.
