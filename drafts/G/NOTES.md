# G — 입자로 읽는 이건상과 agent-colleague (2차)

## 파일

- `index.html` — 장면 7개(입자 무대)와 읽는 절 6개(대표 작업 · 직접 해 보기 · 운영 기록 · 작업물 · 글 · 연결). JS 가 없거나 WebGL2 가 없으면 장면 칸이 그대로 읽는 글로 보인다.
- `assets/particles.js` — 입자 엔진. F 엔진(GPU 에서 위치·속도 갱신, 스프링 복귀, curl-noise 폭발, 오프스크린 캔버스에서 글자 샘플링, 포인터 밀어내기) 위에 2차에서 원근 카메라(이동·회전·기울기), 입자 z 분포, 속도 방향으로 늘어나는 꼬리, HDR 잔상 누적, 블룸, 초점 밖 흐림, 자동 노출을 더했다.
- `assets/site.js` — 직접 해 보기(정책 판정 놀이터). `judge()` 는 D 의 `judge:start`~`judge:end` 블록 그대로다(59줄, `diff` 차이 없음).
- `assets/og-image.png` — 2차 장면 01(이름)을 1200x630 으로 새로 렌더했다. 메타 주소는 `https://kunsanglee.github.io/assets/og-image.png`.
- `shots/` — 장면 PNG 25장씩(1440x900 @1x, 390x844 @2x), 읽는 절 7장씩, JS 끈 전체 화면 1장씩, 스크롤 mp4 2개. 1차 shots 는 모두 지우고 새로 찍었다.
- 1차에 있던 `assets/policy-flow.png`(E 의 그림, 보라·비취가 들어 있다)는 지웠고, 대표 작업 절의 그림 링크도 뺐다.

## 콘셉트

이 사람의 강점은 사내 AI 에이전트를 직접 만들어 15주 동안 굴렸고, 모델이 하는 일과 코드가 막는 일을 나눠 설계했다는 데 있다. 2차에서는 입자 4만 개를 한 덩어리의 빛으로 두고, 카메라가 그 사이를 날아다니며 기록을 차례로 보여 주게 다시 짰다. 장면이 바뀔 때마다 구름이 터지거나, 한 점으로 빨려 들어갔다가 다시 피어나거나, 카메라가 입자 터널을 뚫고 지나간다.

색은 F 의 점토 주황 `#eb663d` · 호박 `#ffa84d` · 크림 `#f6ecdf` 과 흰 코어뿐이고, 바탕은 따뜻한 검정 `#0a0807` 이다. 뜻은 밝기·온도·크기·흐림·꼬리 길이로 나눴다. 사람(질문 · Slack 스레드 · 사람의 답)은 호박, 봇 초안과 판정에 쓰지 않는 글의 내용은 어둡고 흐린 점토 주황, 정책 함수가 보는 사실 · 허용 · 실행 기록 · 세션은 밝고 또렷한 크림에 흰 코어다.

## 1차 약점을 고친 방법

- 연결 장면에서 소용돌이가 연락 문구를 가리던 것: 모든 장면에서 화면 아래 글자 칸(여백 포함) 안의 입자를 흐리게 하고, 연결 장면에서는 이 가림을 가장 세게 둔다. 글자 칸 뒤에는 어두운 받침을 깐다. 소용돌이·폭발 순간(`07a-collapse`, `07b-nova`)에도 버튼과 문구가 읽히는 것을 두 크기에서 확인했다.
- 세션·메시지 개수가 데이터처럼 읽히던 것: 나선 마디 수와 정책 함수 목록 줄 수에는 숫자도 라벨도 붙이지 않았다. 숫자는 235·96초·주별 값·37건만 쓴다.

## 연출

- 원근 카메라: 장면마다 목표 위치·회전·기울기를 정하고 스프링으로 따라간다. 첫 방문 때는 멀리서 날아든다.
- 장면 전환: 터진 뒤 재조립, 한 점으로 붕괴했다가 폭발, 입자 터널 통과.
- 속도 방향 꼬리, HDR 잔상, 블룸, 초점 밖 흐림, 자동 노출(밀집한 모양이 하얗게 타지 않게).
- 스크롤 속도: 빨리 스크롤하면 잔상과 꼬리가 길어지고 카메라가 조금 앞으로 밀린다. 이때 늘어난 잔상은 빛을 번지게만 하고 장면 밝기는 올리지 않는다.

## 상호작용

- 스크롤: 장면을 넘기는 유일한 방법(휠·트랙패드·터치·키보드). 장면 칸 높이(`--len`)만큼 머문다.
- 아래 탭 7개: 누르면 그 장면 칸으로 바로 간다. 탭 밑줄이 장면 진행도를 보여 준다.
- 포인터: 움직이면 입자가 밀려나고, 짧게 누르면 그 자리에서 흩어졌다가 같은 모양으로 돌아온다. 링크·버튼·탭을 누를 때는 흩어지지 않는다.
- 직접 해 보기: 도구 고르기, 스레드 글(봇 글·사람 글·사람의 👍) 넣고 빼기·순서 바꾸기, "같은 호출을 실행한 기록" 켜기, 빠른 예시. 판정은 D 의 `judge()`.
- 주소 옵션: `?fps`(fps·입자 수·dpr 표시), `?n=숫자`(입자 수, 8,000~60,000), `?nofx`(입자 끄고 읽는 판), `?capture`(캡처 스크립트가 시간을 진행).
- 시작 보호: 6초 안에 엔진이 뜨지 않으면 읽는 판으로 돌아간다. 글꼴 CSS 가 실패하면 바로, 늦으면 최대 약 5초 뒤 시스템 글꼴로 샘플링한다. WebGL 컨텍스트를 잃었다 되찾으면 새로고침한다.
- 그리는 해상도는 dpr 2 까지다. 21ms 를 넘는 프레임이 계속 쌓이면(누적 45 초과) dpr 1 로 내린다. 짧은 변이 560px 보다 작거나 터치 화면이면 입자를 32,000개로 줄인다.
- prefers-reduced-motion 은 요청대로 따르지 않는다. 장면 3·7 에 한 점이 밝게 터지는 순간이 한 번씩 있고, 반복해서 깜빡이는 효과는 없다.

## 약한 점

- 실제 아이폰·안드로이드·Safari·Firefox 에서는 돌려 보지 못했다. 모바일 60fps 는 같은 노트북에서 모바일 화면을 흉내 낸 값이라 실기기 성능을 말해 주지 않는다.
- 장면 6 에서 티켓이 판을 지나는 순간 카드가 하얗게 번져 카드 안 줄이 잠깐 보이지 않는다(`06e-allow`). 허용을 보이려는 연출이지만 세다.
- 장면 4 의 감기는 구간(`04b-winding`)은 다른 장면보다 색이 옅어 회색에 가깝게 보인다.
- 장면은 칸에 들어갈 때부터 시간으로 재생된다. 아주 빨리 스크롤하면 장면이 끝나기 전에 다음 장면으로 넘어간다.
- 붕괴·폭발 순간(장면 3·7)은 밝고 움직임이 크다. 움직임에 예민한 사람에게는 부담일 수 있다.
- 영상은 CSS 전환을 손으로 1/30초씩 밀어 찍어서, 글자가 뜨는 타이밍이 실제 브라우저와 조금 다를 수 있다.
- `shots/` 가 92MB 다(PNG 66MB, 영상 25MB). 배포할 때는 빼는 편이 낫다.
- 360px 보다 좁은 화면, 가로로 눕힌 휴대폰은 확인하지 않았다.
