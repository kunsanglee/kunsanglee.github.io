01대표 작업

agent-colleague

Slack 스레드에서 동료처럼 일하는 사내 AI 에이전트

코드 질문에는 근거 파일 경로를 붙여 답하고, 티켓 만들기·DB 조회·PR 올리기도 스레드에서 부탁할 수 있게 만들었습니다. 처음 만든 봇을 Claude Agent SDK 로 다시 설계한 agent-colleague 입니다.

  • TypeScript

4646%

사람이 이어서 말한 스레드

집계 기준

2026년 6월 중순~9월 하순, 팀 코드 질문 채널의 Slack 스레드를 직접 센 사내 운영 기록입니다. 기간 대부분은 1편의 봇이 답했고, 9월 중순에 지금 구조로 바꿨습니다. 이어서 말한 스레드에는 되물음과 정정도 섞여 있고, 답이 맞았는지는 따로 재지 않았습니다.

설계 요점

  1. 01

    말뜻은
    모델이,
    실행 허용은
    코드가

    사람의 답이 승인인지는 모델이 읽습니다. 도구를 실행해도 되는지는 코드가 정하는데, 누가·언제 말했는지, 이미 실행했는지, 운영 DB 라면 예상 비용 같은 사실만 봅니다.

  2. 02

    스레드 하나에 세션 하나

    Slack 스레드마다 에이전트 세션을 하나씩 붙였습니다. 그 스레드의 말·리액션·편집을 모두 읽고, 답할지와 할 일은 모델이 정합니다.

  3. 03

    정해 둔 도구만, 외부에 영향을 주는 일은 초안 먼저

    세션은 목록에 있는 도구만 씁니다. 티켓 생성처럼 외부에 영향을 주는 일을 부탁받으면 초안을 먼저 올리고, 사람이 답한 뒤에 실행합니다.

예시

“티켓 만들어 줘”가 실행되기까지

말뜻은 모델이 읽고, 실행해도 되는지는 정책 함수가 순서만 보고 정합니다. 정책 함수는 도구 호출 직전에 실행 여부를 정하는 코드입니다.

같은 흐름을 그림으로 보기 (새 탭)

도구를 처음 부를 때

  1. 사람

    “이거 티켓으로 만들어 줘”

  2. 모델

    티켓을 만들려는 뜻으로 읽고, 티켓 만들기 도구를 부릅니다.

  3. 정책 함수

    거부합니다. 이 스레드에 봇이 올린 글이 없어서 “초안을 먼저 스레드에 올려라”를 돌려줍니다.

  4. 봇

    티켓 초안을 스레드에 올립니다. Slack 답글은 조건 없이 허용합니다.

답을 받고 다시 부를 때

  1. 사람

    “좋아요, 진행해 주세요”

  2. 모델

    답글을 승인으로 읽고, 같은 도구를 다시 부릅니다.

  3. 정책 함수

    허용합니다. 봇이 이 스레드에 글을 올렸고, 초안 뒤에 사람의 답글이 있고, 같은 요청의 실행 기록이 없습니다. 답글의 내용은 보지 않습니다.

  4. 봇

    티켓을 만들고 실행 기록을 한 줄 남긴 뒤, 티켓 링크를 스레드에 올립니다.

같은 요청이 다시 와도 실행 기록이 있으면 거부합니다.
