# 시안 A — 첫 화면에서 스레드가 쓰여 나간다

## 콘셉트

첫 화면 오른쪽(모바일은 제목 바로 아래)에서 대화 스레드 하나가 실제로 쓰여 나갑니다. 동료가 코드 질문을 입력하면 에이전트가 코드를 읽는 동안 질문에 👀 가 붙고, 근거 파일 경로 두 개를 단 답이 올라옵니다. 이어서 "이거 티켓으로 만들어 줘" → 초안 → 사람의 답 → 도구 호출 순서로 흘러가고, 도구를 실행하기 직전에 카드가 어두운 "코드가 보는 것" 화면으로 바뀝니다. 이때 글자는 회색 막대로 가려지고 누가·언제 썼는지와 실행 기록만 남은 채, 코드가 사실 세 가지를 하나씩 확인해 "허용"을 냅니다. 처음부터 끝까지 16초입니다. 아래로 스크롤하면 스레드가 역할 색 줄로 접히고, 그 위로 15주 운영 기록·설계 요점·작업물이 올라와 덮습니다. Slack 화면은 베끼지 않았습니다. 사람(호박색 원)·모델(보라색 네모)·정책 검사(비취색 마름모)·외부 시스템(파란 삼각형)을 모양과 색으로 나눈 세로 타임라인으로 새로 그렸습니다.

## 왜 시선을 끄는지

- QR 을 찍고 들어온 사람이 처음 몇 초 안에 질문 → 근거를 단 답 → 초안 → 사람의 답 → 검사 → 실행을 움직임으로 봅니다. 설명을 다 읽기 전에 무엇을 만든 사람인지 보이도록 했습니다.
- 재생 중에 카드 색이 통째로 바뀌는 때는 정책 검사 4.5초뿐입니다. 이 사람의 설계 요점("말뜻은 모델이, 실행 허용은 코드가")이 그 순간에 눈에 들어옵니다.
- 제목 바로 아래에 235건·96초를 두어, 재현한 예시 옆에 실제로 잰 운영 기록이 함께 보이게 했습니다.
- 스크롤하면 대화가 역할 색 줄로 압축되면서 바로 아래 판의 운영 기록으로 넘어갑니다.

## 인터랙션

1. 자동 재생(16.4초). 글꼴이 준비되면 시작하고, 늦어도 0.9초 뒤에는 시작합니다. 재생/일시정지, 처음부터 다시 보기 버튼이 있습니다(둘 다 44px 이상).
2. "코드가 보는 것" 스위치: 아무 때나 켜고 끌 수 있습니다. 재생이 끝난 뒤 켜면 "같은 호출이 지금 다시 오면" 검사가 나오고, 봇의 마지막 글 뒤에 사람의 답이 없고 실행 기록이 1줄 있어 "거부"가 됩니다.
3. 스크롤 접힘: 첫 화면이 제자리에 붙어 있고 아래 판이 덮으며 올라옵니다. 그동안 스레드는 역할 색 줄로 접히고 재생은 멈췄다가, 맨 위로 돌아오면 이어집니다. 창 높이가 560px 보다 낮으면 접힘을 쓰지 않습니다.
4. 설계 요점의 "예시에서 정책 검사 보기 / 예시를 처음부터 보기 / 예시에서 초안 단계 보기" 버튼: 맨 위로 올라가 데모의 해당 장면부터 재생합니다.
5. 운영 기록: 화면에 들어오면 숫자가 0부터 올라가고 235칸이 차례로 채워집니다.
6. 브라우저 탭이 가려지면 재생을 멈추고, 다시 보이면 이어 갑니다.
7. `prefers-reduced-motion: reduce`: 마지막 장면을 멈춘 채로 보여 줍니다. 재생 버튼은 숨기고 스위치만 남기며, 접힘·숫자·칸 애니메이션도 끕니다.
8. JavaScript 가 꺼져 있으면 마지막 장면과 요약 문장이 그대로 보이고, 누를 수 없는 스위치는 숨깁니다.

## 알려진 한계

1. 정책 검사 장면은 4.5초라, 그 뒤에 화면을 본 사람은 스위치를 누르거나 설계 요점의 버튼을 눌러야 다시 볼 수 있습니다.
2. 큰 화면(1920x1080)에서는 카드 높이를 800px 로 묶었습니다. 재생 초반에는 카드 아래쪽이 비어 있다가 스레드가 자라며 차고, 마지막 장면에는 빈칸이 없습니다.
3. 모바일(390x844)에서는 스레드 창이 442px 라, 마지막 장면에서는 앞쪽 질문과 답이 위로 밀려 보이지 않습니다. 멈춘 뒤 창 안을 스크롤하면 볼 수 있습니다.
4. `og:image:alt`·`twitter:image:alt` 에는 "…만들고 운영합니다"가 남아 있습니다. 공용 `og-image.png` 에 적힌 글을 그대로 옮긴 것이라, 이미지(시안 폴더 밖)를 바꿀 때 함께 고쳐야 합니다.
5. 실제 휴대폰(iOS Safari, 안드로이드 Chrome)에서는 확인하지 못했습니다. headless Chrome 의 기기 크기 흉내로만 확인했습니다.
6. 390 폭 스크린샷은 브리프가 말한 iframe 래퍼 대신 Chrome DevTools Protocol 의 기기 크기 흉내(`Emulation.setDeviceMetricsOverride`, 모바일 모드)로 찍었습니다. 문서 폭이 390px 이고 가로 넘침이 없는 것을 함께 확인했습니다.

## 확인한 것

- 화면 크기: 390x844, 375x667, 360x780, 768x1024, 1024x768, 1280x800, 1440x900, 1920x1080. 모든 크기에서 가로 넘침 0.
- 390 폭에서 누를 수 있는 요소 24개 모두 44px 이상(움직임 줄이기 설정을 켠 경우 포함).
- 실제 재생으로 재생·일시정지·다시 보기·스위치·스크롤 접힘·설계 요점 버튼을 차례로 눌러 보았고, 콘솔 오류는 0건이었습니다.

- 촬영용 장면 고정 코드는 `/tmp` 의 임시 사본에만 넣었고, 이 폴더의 `index.html` 에는 없습니다.
