# 시안 D — 정책 함수가 보는 것을 스크롤로 겪게 하는 원페이지

## 콘셉트

이 사람의 강점은 "말뜻은 모델이 읽고, 실행해도 되는지는 코드가 누가·언제·이미 실행했는지 같은 사실만 보고 정한다"는 설계를 실제 운영까지 가져간 데 있다고 봤습니다. 그래서 페이지를 그 설계를 눈으로 겪는 한 줄기 무대로 짰습니다. 첫 화면은 큰 제목과 노란 96초, 그리고 에이전트가 답한 질문 스레드 235건을 선 235개로 주마다 쌓은 그림으로 시작합니다. 아래로 내리면 티켓 부탁 하나를 재현한 대화가 스크롤한 만큼 진행되고, 도구를 다시 부르는 순간 글의 내용은 막대로 가려진 채 글을 쓴 시각만 "정책 함수가 본 것" 칸으로 날아갑니다. 예시 마지막의 스레드 띠는 화면에 머문 채 "직접 해 보기" 칸까지 내려가 자리를 잡고, 방문자는 거기서 글을 넣고 빼고 순서를 바꾸며 실제 정책 코드와 같은 조건으로 계산한 판정을 봅니다. 뒤쪽은 종이색 면으로 바꿔 15주 기록, 설계 요점, 작업물, 글을 차분히 읽게 했습니다. 색은 잉크 검정과 종이색 두 면에 강조색 노랑 하나만 쓰고, 사람(호박)·봇(보라)·허용(초록)·거부(빨강)는 역할 색으로 고정했습니다. 글꼴은 Pretendard 하나와 코드용 고정폭 글꼴입니다.

## 처음 몇 초에 무엇이 보이는지

- 첫 화면(390x844, 390x664 모두)에 이름·직무, 제목 네 줄, 96초와 그 설명(첫 질문에서 첫 답까지 중앙값 · 15주 · 질문 스레드 235건 · 1편 봇부터 이어진 운영 기록), 두 버튼이 들어갑니다. 844 높이에서는 선 그림과 설명까지 보입니다.
- 숫자를 그림 재료로 썼습니다. 선 하나가 질문 스레드 하나이고, 선이 주별로 차오른 뒤 노란 세로줄이 한 번 지나가며 선을 밝힙니다. 마우스를 대면 선이 밀려나고, 화면을 누르면 물결이 퍼집니다.
- 예시는 자동 재생하지 않습니다. 스크롤한 만큼 진행하므로 30초 안에 넘기는 사람도 손가락을 움직이는 동안 장면이 바뀝니다. 1200px 미만 화면에서는 화면 높이의 2.2배만큼 스크롤하면 여섯 단계가 모두 지나갑니다(1200px 이상은 3배).
- 가림 장면 하나로 "글의 내용은 판정에 쓰지 않는다"가 설명 없이 보입니다.
- 예시에서 놀이터로 넘어갈 때 화면을 끊지 않습니다. 같은 띠가 그대로 이어집니다.

## 장면별 연출 의도

1. **첫 화면.** 제목 네 줄이 70ms 간격으로 올라오고 "동료처럼"만 노란 면으로 칠했습니다. 데스크톱은 왼쪽 제목, 오른쪽 96초로 나눠 빈칸을 남기지 않았고, 바닥 전체를 선 그림이 채웁니다. 선 그림은 화면 밖으로 나가거나 움직임이 멈추면 다시 그리지 않습니다.
2. **대표 작업 소개.** 원본 #featured 의 제목·설명·기술 배지를 두고, "스크롤하는 만큼 진행됩니다"로 다음 장면을 다루는 법을 알려 줍니다.
3. **재현한 예시(고정 무대, 6단계).** 카드 머리에 "재현한 예시 · 실제 대화가 아닙니다"를 붙였습니다. 순서는 policy-flow 그림과 같습니다. 사람이 부탁하면 모델이 티켓 도구를 바로 부르고, 정책 함수가 거부하고, 모델이 초안을 올리고, 사람이 답하고, 같은 도구를 다시 부르면 허용합니다. 다시 부르는 순간 노란 세로줄이 카드를 훑으며 글의 내용을 막대로 가리고, 봇 글과 사람 글의 시각만 남아 "정책 함수가 본 것" 칸(데스크톱은 오른쪽 열, 모바일은 아래에서 올라오는 판)의 행으로 날아갑니다. 가로로 눕힌 휴대폰에서는 이 칸을 오른쪽 열로 옮겼습니다. 칸의 세 행(봇이 올린 마지막 글, 그 뒤 사람 글, 같은 호출의 실행 기록)이 차례로 확인되고 "허용" 도장이 찍힌 뒤 실행 기록 한 줄이 생깁니다. 마지막 단계에서 대화가 접히고 "정책 함수가 본 이 스레드" 띠(봇 글 → 사람 글 → 도구 호출)만 남습니다.
4. **띠 옮김.** 예시 띠와 놀이터 띠 사이를 스크롤하는 동안 띠 사본이 화면에 머물며 놀이터 칸의 모양과 위치로 바뀌어 갑니다. 옮기는 동안에는 사본 뒤가 흐려 보이는 유리 판이 되고 살짝 들렸다가 내려앉습니다. 스크롤을 멈춘 뒤 0.48초가 지났을 때 사본이 놀이터 제목을 가리고 있으면, 또는 놀이터를 누르거나 키보드로 들어가면 사본이 실제 칸에 내려앉습니다. 이야기 끝에서 멈춘 경우에는 띠 모양 그대로 둡니다. 이야기 끝보다 위로 올라갔다가 다시 내려오면 옮김이 처음부터 다시 이어집니다. 실제 칸과 사본의 위치 차이는 모바일 390x844 에서 0.7px, 데스크톱 1440x900 에서 0.2px 로 쟀습니다.
5. **직접 해 보기.** 도구 다섯 개(티켓 만들기, 코드 고쳐 PR 올리기, 운영 DB 질의, 스레드에 글 올리기, 코드 읽기)를 고르고, 스레드 띠의 봇 글·사람 글·사람의 👍 를 넣고 빼거나 끌어서 순서를 바꾸고, "같은 호출을 실행한 기록" 스위치를 켜면 판정과 확인 순서가 바로 바뀝니다. 오른쪽(모바일은 아래) 판정 칸에는 확인한 조건이 위에서부터 예·아니오·확인 안 함으로 쌓입니다. 모바일에서는 조작하는 동안 판정이 화면 밖으로 밀리지 않도록 조작 칸 아래에 작은 판정 줄을 붙였습니다. "사람 답 필요"는 코드에서는 거부(deny)이며, 답하면 허용될 수 있는 거부를 색으로 나눴다고 아래에 밝혔습니다.
6. **운영 기록(종이색 면).** 15주·235건·96초·46% 를 숫자 롤링으로 보여 주고, 첫 화면의 선 그림을 밝은 판으로 다시 씁니다. 여기서는 기둥을 가리키거나 누르면(키보드는 화살표) 그 주의 건수가 읽힙니다. 마지막 주(9/21)는 이틀치라 점선으로 둘렀습니다. 아래에 기간·1편 봇·9월 중순 구조 전환·정확도 미측정 문장을 그대로 둡니다.
7. **설계 요점.** 원본의 세 요점을 두고, 첫 요점에는 같은 답글("좋아요, 진행해 주세요")을 "모델이 읽는 것"과 "정책 함수가 보는 것"으로 바꿔 보는 단추를 붙였습니다. 옆에 policy-flow 그림(지연 로딩)과 1·2편 링크를 둡니다.
8. **작업물·글.** 행 전체가 링크이고, 데스크톱에서는 커서 옆에 목적지 주소가 작게 따라붙습니다.
9. **연결.** 원본의 "코드가 말하게 하는 개발자"와 GitHub·Medium 버튼, 맨 아래 큰 이름. 끝까지 내려오면 이름 글자가 하나씩 굵어지고, 데스크톱에서는 마우스가 가까운 글자가 밝아집니다.

## 판정 로직 대조 방법과 결과

- 방법: `src/policy/index.ts` 와 그 의존 파일을 작업 폴더 밖(`/tmp/d_shoot/pc`)에 복사하고 import 확장자만 `.ts` 로 바꿨습니다(diff 로 두 줄만 다름을 확인). 페이지의 `/* judge:start */ … /* judge:end */` 구간을 그대로 떼어 내 실행하고, 놀이터에서 만들 수 있는 모든 상태를 실제 `decide()`·`pathVerdict()` 에 넣어 결과 종류(허용·거부)와 거부 이유의 종류를 비교했습니다. 상태는 도구 5개 × 글 세 개의 유무와 순서 × 실행 기록 유무 × 운영 DB 의 읽기·쓰기와 비용 세 경우 × 경로 안·밖을 모두 펼쳤습니다. "사람 답 필요"는 코드의 deny 와 순서 이유로 맞췄습니다.
- 결과: 상태 1,920개, 불일치 0. 최종 파일로 다시 돌린 결과입니다.
- 코드 읽기는 `decide()` 에서는 항상 허용이고 경로 검사는 `pathVerdict()` 가 하므로, 실제 코드도 같은 두 단계를 거치는지 확인한 뒤 대조에 `pathVerdict()` 를 썼습니다.
- 놀이터에 없는 경우(이슈 삭제의 프로젝트 제한, 운영이 아닌 DB 질의, Bash 명령 검사 등)는 대조하지 않았고 페이지에도 넣지 않았습니다.

## 알려진 한계와 확인하지 못한 것

- 실제 iPhone Safari·안드로이드 Chrome 에서는 확인하지 못했습니다. `svh` 단위, `backdrop-filter`, 긴 sticky 무대의 스크롤 감각은 기기에서 봐야 합니다.
- 기울기 반응은 기기에서 확인하지 못했습니다.
- 화면 읽기 프로그램(VoiceOver·TalkBack)으로 실제로 읽어 보지 않았습니다. ARIA 속성과 `aria-live` 문장이 바뀌는 것까지만 확인했습니다.
- 가로 화면은 에뮬레이션으로만 봤습니다. 568x320(4인치 휴대폰 가로)에서는 첫 화면에 96 이 들어오지 않고, 이야기 무대에서 단계 설명과 판정 칸이 겹치며, 마지막 띠가 카드 밖으로 나갑니다. 폭이 600px 미만이라 세로 배치를 그대로 쓰기 때문이고 고치지 않았습니다.
- 글꼴 하위 파일 21개(약 600KB)가 첫 방문에 내려옵니다. 글자는 시스템 글꼴로 먼저 보이고 바뀝니다.
- `index.html` 이 A·C 의 두 배쯤(gzip 39KB)입니다. 빌드 도구 없이 손으로 읽을 수 있게 두느라 줄이지 않았습니다.
- 데스크톱에서 마우스를 움직이면 기본 커서를 숨기고 원형 커서를 씁니다. 싫어하는 사람이 있을 수 있습니다. 움직임 줄이기 설정에서는 기본 커서 그대로입니다.
- 초기화 오류가 나서 페이지를 움직임 없는 판으로 다시 불러오면, 같은 탭에서는 `sessionStorage` 표시가 남아 이후에도 움직임 없는 판으로 뜹니다.
- 예시의 시각 네 개는 원본에 없는 꾸밈 값입니다(위 "쓴 사실과 출처" 참고).
